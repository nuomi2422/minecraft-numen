## 红线清单（全部实测通过，冻结）

### RL-1 · 规划能看到真实背包（数据链地基）
- **内容**：`/goal` 规划时，实时扫描的持有资产必须进入规划输入（不是空背包）。
- **证据**：会话文件 `context.jsonl` 含 `<rdd>` instruction（135+ 次）+ `report_task_concern`（137+ 次）；规划请求出现 `diamond_pickaxe/obsidian/hay_block`。
- **修复提交**：`249b2bf7`（A+B+C：规划前刷新/无条件缓存/空背包显式告知）
- **通过时间**：2026-09-25

### RL-2 · 依赖门读实时背包（不死锁）
- **内容**：背包有物资 → 依赖门放行、链推进（不再"有装备却 primary_waiting"）。
- **证据**：`13× subtask_completed` + `6× dependency_met`；P0 全过 → P1 推进。
- **修复提交**：`8616458e`（`activateCurrentWithSnapshot`）
- **通过时间**：2026-09-25

### RL-3 · 早期阶段不被误挂高风险门
- **内容**：主世界据点/食物等早期阶段的 `waitFor` 必须为空（不被误判成下界/末地）。
- **证据**：P0 `waitFor=[]`。
- **修复提交**：`8616458e` + `f38b4188`（风险词二次收紧，"备"字误判）
- **通过时间**：2026-09-25

### RL-4 · 下界/末地阶段自带硬规范（= 规划期 waitFor 硬门）
- **内容**：规划出的下界阶段必须自带 全套保护硬规范（两套钻石甲 + 抗火药×3 + 食物 + 箭 + 床）；末地同理。由**代码 `injectWaitFor`** 产生，非提示词祈祷。
- **证据**：P3 下界 `waitFor` = 12 项（含 `fire_resistance_potion×3`/`white_bed`/`diamond_*×2`）；P6/P7 末地全套。
- **通过时间**：2026-09-25
- **⚠️ 范围澄清（重要）**：RL-4 只保证"**规划出的下界阶段自带 waitFor，且进入该阶段时依赖门会拦**"。
  它**不等于"风险门硬拦"**——RL-4 **不能阻止 Numen 在早期阶段自己跑去下界**。

### RL-8 · 风险门硬拦（防死亡循环根因）· ⚠️ 代码已修，**真机未验证**
- **内容**：Detector 激活**下界/末地级**前，`RiskGate.checkWithRecovery`（物资+药水+恢复点）**不达标不派工**。
- **代码提交**：`7cf0ca05`（`RddDetector.riskGateAllows` + `hasBoundRespawn`）
- **状态**：⚠️ **代码已接、编译过、273 测绿，但【未真机验证触发】**——当时没构造出"装备不足被拦"的场景。
- **待验证**：进游戏给一个"装备不足的下界级"，确认 `primary_risk_gated` 事件 + 不派工。
- **与 RL-4 的区别**：RL-4=进入下界阶段时**依赖门**拦（该阶段初始创建时即带）；RL-8=**执行前**的**风险专项**拦（含恢复点/药水语义，防早期乱跑送死）。

### RL-5 · 双向协商（士兵能开口 + 指挥官能改单）
- **内容**：Numen 认为命令不合理/做不到时，能主动调 `report_task_concern`（REJECT/COUNTER+建议）；指挥官收到后改单/重规划（不被预算一口回绝）。

- **修复提交**：`6b3d2370`（协商独立预算）+ `c7aee61c`/`90f19120`（通道+提示）
- **通过时间**：2026-09-25

### RL-6 · 死亡资产失效 + LOST 记录
- **内容**：同伴死亡 → 背包类资产立即失效；死亡瞬间真实持有的（**含直接给的**）逐条记 `LOST`（带死亡坐标+时间）。

### RL-7 · 床边复活（死亡回自己绑的床旁）
- **内容**：同伴绑过床后死亡，复活必须落在**该床旁安全落点**（不是主人旁/世界出生点）。
- **证据**：绑床 `9848,64,10164` → `debug_kill` → 复活 `(9849.5,64,10164.5)`（两次通过）。
